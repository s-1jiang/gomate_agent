# 文字聊天与检索来源

页面注册登录后可直接提问。后端读取当前会话最近 20 条消息（默认最多 40000 字符），经 Supervisor 路由后保存回复并自动展示。普通问答可用一次非流式 DeepSeek 调用完成；地图需求进入多 Agent 查询和审查流程，见 [地图搜索](MAP_SEARCH.md)。游玩规划输出结构化行程与时间校验，并可选接入 Tavily，见 [同城行程](ITINERARY.md)。当前没有流式输出。

## 添加知识

右上角“知识库”支持选择 TXT / Markdown 或粘贴文本，单份不超过 100000 字符，文件不超过 300 KB，每个用户最多 100 份有效资料。当前不支持 PDF / OCR。只解析用户提交的文本，不根据来源名称读取磁盘路径或抓取网页。

- “仅当前会话”：只能在来源会话中检索；需先创建会话。
- “我的所有会话”：当前用户的会话可检索，其他用户不可见。
- 提问时，模型会接收当前会话上下文及最多 5 个授权原文片段。资料本身保存在本地 SQLite；没有外部向量服务调用。

当前采用中文二元词和英文单词的本地关键词匹配，**没有 Embedding、向量召回或 Rerank**。页面与 `/capabilities` 明确标识 `lexical`，这是可使用的基础检索版本，尚未实现框架文档中的完整混合检索。没有匹配结果时，回复标注“未检索到相关资料，本次回复由模型生成”。

## 来源标签

回答中的 `[R1]`、`[R2]` 对应同一条回复下面的“检索来源”。展开可查看：

- 资料名称、用户提供的来源说明、文档版本和原始行号。
- 原文片段、文档 ID、片段 ID、检索时间和资料范围。
- 片段及整份文档的 SHA-256。入库只将 CRLF / CR 换行规范为 LF，其余正文及首尾空行保留；哈希基于该规范化文本。

来源列表由后端实际检索结果生成，模型不能创建列表。`cited: true` 只表示正文出现了对应引用标记，页面区分“正文已引用”和“已召回，正文未引用”。未提供的 `[R编号]` 会替换为“来源未核实”。标签证明片段从哪份入库资料召回，**不证明用户提供的来源名称真实，也不证明模型对原文的解释正确**。

每轮编号重新开始，历史引用在发送给模型时标记为历史引用，不复用历史编号作为新证据。资料正文作为不可信数据提供，不改变系统权限或工具配置。

删除后资料立即退出检索、原文片段被清理，历史引用显示“来源已删除，内容不可查看”。如果资料在生成回复期间被删除，该回复不会提交。删除资料不会删除已经保存的历史问答；需要一并删除时请删除对应会话。

## 接口

需要 Bearer Token；用户身份从登录信息取得，不接受请求传入 user_id。

| 接口 | 作用 |
| --- | --- |
| `POST /api/v1/knowledge/documents` | 添加文本，指定 title、source_ref、content、scope 和 session_id |
| `GET /api/v1/knowledge/documents?session_id=...` | 列出用户资料与指定会话资料；省略会话时只列用户资料 |
| `POST /api/v1/knowledge/search` | 诊断检索，传 session_id、query、limit（1–5） |
| `DELETE /api/v1/knowledge/documents/{id}` | 删除自己拥有的资料并清理原文片段 |
| `GET /api/v1/conversations/{id}/messages` | 消息包含 retrieval_status 和 sources，读取时重新校验来源可见性 |

文档当前不可就地更新；修改资料时删除后重新添加，会产生新的文档 ID，版本从 1 开始。所有权和会话可见性在计算 Top-K 前过滤。

## 验证和运行

单进程运行；每个会话只允许一个活跃任务。幂等请求不重复调用模型；取消会中止在途客户端请求，超时、删除会话、租约过期和旧 fencing token 均不能写入迟到回复。已发送的供应商请求可能已经产生费用，取消不代表供应商退款。

`python scripts/smoke_chat.py` 使用临时数据库、假密钥和本机模拟供应商验证 HTTP 聊天与引用链路，不向 DeepSeek 发送真实密钥或用户资料。普通 `scripts/smoke_docker.py` 默认也不调用外部供应商。

DeepSeek 请求格式依据 [官方 Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)；多轮上下文依据 [官方多轮对话说明](https://api-docs.deepseek.com/guides/multi_round_chat/)。
